# 온길 · 학교 상담실 — 가입·상담 체험판 (2.0)

학생과 교사 역할을 같은 기기의 같은 브라우저 탭에서 바꿔 가면서 가입, 승인, 상담 예약, 상담 내역과 검사 결과지를 실습합니다. 실제 이름·연락처·고민 대신 가상 별명과 예시를 사용하세요. 비밀번호, GitHub·ChatGPT 계정, Supabase 가입은 필요 없습니다.

## 1. 먼저 내가 학생으로 가입해 보기

1. ZIP을 풀고 최상위의 **index.html**을 브라우저로 엽니다. 첫 화면에 **가입 체험하기 / 김하늘로 바로 체험하기**가 보이면 새 버전입니다.
2. **가입 체험하기**를 선택합니다. 가상의 별명(예: 별빛고래), 학교, 학년·반·번호를 입력해 가입 신청을 보냅니다. 이미 사용 중인 학적이라는 안내가 나오면 다른 번호를 선택하세요.
3. 승인 대기 화면에서 교사 역할로 이동해 방금 등록한 별명과 학교를 확인한 뒤 **가입 승인**을 누릅니다. 학생으로 돌아가면 그 별명으로 시작합니다. 새 학생의 예약·상담 기록·검사 결과는 비어 있습니다.
4. **김하늘로 바로 체험하기**는 가입 과정을 건너뛰고 이미 승인된 가상 학생의 자료로 시작합니다. 예시 상담 내역이나 흥미검사 결과지를 먼저 보고 싶을 때 알맞습니다.
5. 앱을 새로고침하면 시작 화면으로 돌아가며 연습한 내용은 사라집니다. 파일을 더블클릭해 실행할 때도 연습할 수 있으나 학생에게 보여줄 접속 QR은 GitHub Pages 배포 후 웹 주소에서 확인하세요.

## 2. GitHub Pages에 올리기 — 배포할 파일은 index.html 하나

**이미 이전 온길 체험판을 GitHub에 올렸다면:** 같은 저장소의 같은 폴더에 이 버전의 index.html을 올려 교체하고 Commit changes를 누르세요. Pages 주소를 그대로 쓰면 배포 완료 후 기존 QR도 그대로 연결됩니다. 파일명이 index(1).html처럼 바뀌지 않게 확인하세요. 아래 새 저장소 절차는 처음 배포할 때만 필요합니다.

**기존 자소서 프로그램을 보존하려면 새 저장소를 쓰세요.** ZIP을 통째로 올리지 말고, 압축을 푼 뒤 파일명이 정확히 소문자 index.html인 파일을 선택하세요. 배포용 파일 안에 코드·스타일·아이콘·QR 생성기가 들어 있습니다.

1. 선생님의 GitHub에 로그인한 뒤 오른쪽 위 **+ → New repository**를 선택합니다.
2. 예를 들어 저장소 이름을 **ongil-demo**로 입력합니다. GitHub Free에서 공개 체험판으로 운영하려면 **Public**을 선택합니다. **Add a README file**을 켜면 빈 저장소 안내 화면을 건너뛸 수 있습니다. **Create repository**를 누릅니다.
3. 새 저장소의 **Code → Add file → Upload files**에서 **index.html**을 넣고 **Commit changes**로 저장합니다. 파일 목록의 첫 화면에 index.html이 보여야 합니다. README 파일이 함께 있어도 괜찮습니다.
4. 해당 **저장소 안의 Settings → Pages**를 엽니다. 계정 프로필의 Settings와 다릅니다. **Build and deployment → Source → Deploy from a branch**를 선택합니다. **main**(또는 파일을 올린 브랜치)과 **/(root)**를 선택한 후 **Save**를 누릅니다.
5. 배포가 끝나면 같은 Pages 화면의 **Visit site**로 엽니다. 배포 중에는 잠시 기다려 주세요. 예시 주소 형식: https://계정명.github.io/저장소이름/ . github.com으로 시작하는 파일 보기 화면은 학생용 실행 주소가 아닙니다.
6. 열린 체험판 상단의 **공유 QR**을 눌러 교실 화면에 띄웁니다. 학생은 카메라로 읽거나 주소로 직접 접속합니다. 학생에게 GitHub 계정이나 ChatGPT 계정은 필요하지 않습니다.

## 3. 같은 탭에서 학생 → 교사 → 학생 실습

| 순서 | 역할·작업 | 확인할 결과 |
|---|---|---|
| 1 | 학생: 가입 신청. 교사: 같은 학교의 가입 대기에서 해당 학생을 승인 | 새 학생의 별명으로 처음부터 이용 |
| 2 | 학생: 상담 예약·신청에서 선생님, 날짜·시간, 가상 신청 사유 선택 | 내 신청에 ‘신청 대기’ 표시 |
| 3 | 교사: 방금 들어온 예약의 학생·시간 확인 후 확정 | 학생으로 돌아가면 같은 예약에 ‘예약 확정’ 표시 |
| 4 | 교사: 해당 학생의 상담 기록 작성. 교사용 비공개 메모와 학생에게 전할 요약을 구분하고 공유 여부를 선택해 저장 | 교사는 상담 내역에서 작성한 기록을 다시 열 수 있음 |
| 5 | 학생: 내 상담 내역 확인 | 공유한 요약만 보이고 교사 비공개 메모는 보이지 않음 |
| 6 | 학생: 진로 흥미 탐색 12문항에 응답하고 결과 저장, 검사 결과지 열기 | 내 별명·실시일·6개 영역 점수를 다시 확인 |

같은 탭에서 학생과 교사 역할을 전환하세요. 다른 휴대폰에서 신청·승인을 주고받는 방식이 아닙니다. 두 학교 중 어느 학교를 선택하든 해당 학교의 교사로 승인과 예약을 연습합니다. 실제 학생 정보를 받기 위한 서비스가 아닙니다. 흥미 탐색은 수업용 활동이며 표준화된 적성검사나 심리 진단이 아닙니다.

## 4. 저장·권한·운영의 범위

- 모든 연습은 현재 탭의 메모리에서만 일어납니다. **새로고침하거나 탭을 닫으면 입력한 내용이 없어집니다.** 역할 전환만 하면 같은 탭의 연습 내용이 이어집니다.
- 앱은 상담 입력이나 흥미 결과를 서버, GitHub, 외부 QR 서비스로 전송하지 않습니다. 웹 주소로 접속하는 데 필요한 정적 페이지 요청은 호스팅 서비스로 갑니다. 외부 커리어넷 링크는 사용자가 직접 눌렀을 때 별도 사이트를 엽니다.
- 학생 150명이 참여해도 교사 컴퓨터로 150건이 모이지 않습니다. 다른 사람의 기기와 시간표·검사 결과를 공유하지 않습니다.
- 학생·교사·관리자 역할 전환과 가입 승인은 가상 화면 체험을 위한 기능입니다. 실제 사용자 인증·학교 소속 확인이나 상담 플랫폼의 운영 보안을 제공하지 않습니다. 관리자 역할에서 바꾼 공지·홈 설정도 **현재 탭에서만** 반영됩니다.
- 공개 저장소에는 학생 정보·상담 기록·서버 비밀키를 올리지 마세요. 테스트가 끝나도 이 파일에 실제 상담을 접수하지 마세요.
- 나중에 실사용하려면 별도의 로그인·데이터베이스·서버 쪽 학교별 권한 검사를 연결해야 합니다. Supabase를 가입하는 것만으로 연습판이 운영판으로 바뀌지는 않습니다.

## 5. 문제가 있을 때

- **여전히 김하늘로 바로 열림:** 예전 파일을 열었을 가능성이 있습니다. ZIP을 새 폴더에 풀어 그 안의 index.html을 열어 보세요. GitHub에서는 별도 저장소를 다시 만들 필요 없이, 이전 체험판 저장소의 같은 위치에 index.html을 같은 이름으로 교체하고 배포가 끝난 뒤 페이지를 새로고침하세요. 이전의 ChatGPT 비공개 사이트는 별개입니다.

- **404 또는 저장소 설명만 보임:** Pages의 브랜치와 폴더, index.html의 대소문자와 위치를 확인하세요. index.html.txt이거나 상위 폴더가 한 겹 더 들어가지 않았는지 보세요. Pages 배포가 완료된 뒤 Visit site로 접속합니다.
- **HTML 코드가 글자로 보임:** GitHub 파일 미리보기 화면입니다. 저장소의 Settings → Pages → Visit site로 이동하세요.
- **학생의 신청이 내 컴퓨터에 안 보임:** 정상입니다. 연습 때는 학생이 사용한 기기의 같은 탭에서 역할을 교사로 바꿉니다.
- **QR이 안 보임:** PC에서 파일을 더블클릭한 주소는 다른 기기에서 열 수 없습니다. 배포된 Pages 웹 주소에서 ‘공유 QR’을 여세요.
- **업데이트:** 같은 저장소 위치에 새 index.html을 같은 이름으로 업로드하고 Commit changes를 누릅니다. 주소와 QR은 Pages 주소가 같으면 그대로 쓸 수 있습니다.

## 6. 구성·개발

- index.html: 바로 올려 사용할 완성본. 배포 시 다른 파일은 필요 없습니다.
- README.md: 이 안내서.
- source/: 수정 가능한 React/TypeScript 원본, 스타일, 라이선스와 빌드 도구. 실제 상담 운영용 백엔드는 포함하지 않습니다.

코드를 수정할 때만 Node.js 22 이상과 npm이 필요합니다. 압축을 푼 source 폴더에서 npm install 후 npm run build를 실행하면 source/build/index.html이 생성됩니다. 이 파일을 GitHub 저장소 최상위의 index.html로 교체하세요. 배포용 단일 파일에는 스크립트 무결성 검사가 포함되어 있으므로, 내려받은 HTML 속 자바스크립트를 직접 수정하지 말고 원본을 수정한 뒤 다시 빌드하세요.
